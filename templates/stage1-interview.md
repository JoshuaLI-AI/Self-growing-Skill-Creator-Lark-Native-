# Stage 1 需求访谈引导 Prompt 模板
# 在 §2.1 标准模式 Step 1 中使用

## 访谈目标

通过自然对话收集以下五类信息，为后续知识空间搭建提供输入：

1. **技能目标** — 这个技能帮用户做什么
2. **触发场景** — 用户通常怎么说来启动它
3. **输出格式** — 技能产出的形式
4. **专业领域** — 领域特有术语和规则
5. **领域变量** — 影响处理逻辑的关键变量（枚举/文本）

## 访谈流程

### 开场白

> "好的，我来帮你搭建一个基于飞书知识库的「[用户提到的领域]」技能。为了构建最适合你的知识结构，我需要了解一些基本情况。我们边聊边整理，不会很复杂。"

### 第一轮：理解目标（必问）

**核心问题：**
- "这个技能主要帮你做什么？能描述一个典型使用场景吗？"
- "你希望它输出什么格式？一份审核报告？一个检查清单？还是直接修改文档？"

**记录字段：** skill_goal, output_format

### 第二轮：触发场景（必问）

**核心问题：**
- "通常什么情况下你会需要用到它？你会怎么向它描述你的需求？"
- "有没有一句简短的话能概括什么时候该用它？"

**记录字段：** trigger_scenario → 写入子技能 description

### 第三轮：专业领域（必问）

**核心问题：**
- "这个领域有什么专业术语或特殊规则我需要注意的？"
- "有没有什么'行话'或缩写我需要知道的？"

**记录字段：** domain_context, terminology

### 第四轮：领域变量（关键，可能多轮）

**引导方式：**
> "接下来是最关键的部分——影响你处理逻辑的关键变量。比如在合同审核中，'谈判地位'（甲方/乙方）会完全改变建议方向。你的领域中有哪些这样的变量？"

**对每个变量深入确认：**

| 收集项 | 引导话术 | 示例回答 |
|--------|----------|----------|
| 变量名称 | "这个变量叫什么？" | 谈判地位 |
| 变量类型 | "它是从固定选项中选，还是自由填写的？" | 固定选项 |
| 可选值（若 enum） | "有哪些可能的取值？" | 甲方、乙方、中立方 |
| 识别提示 | "AI 怎么从用户的话中判断这个变量的值？" | 从"我们代表..."等表述中识别 |

**建议收集数量：** 3-7 个领域变量。过少导致检索精度不足，过多增加复杂度。

### 结束确认

展示完整摘要：

```
┌─────────────────────────────────────┐
│ 技能目标：    [goal]                │
│ 触发场景：    [trigger]              │
│ 输出格式：    [format]               │
│ 领域背景：    [domain]               │
│                                     │
│ 领域变量（N 个）：                   │
│   1. [name] ([type]) - [hint]       │
│   2. [name] ([type]) - [hint]       │
│   ...                               │
└─────────────────────────────────────┘
```

> "以上信息正确吗？有需要修改或补充的吗？确认后我就开始搭建飞书知识空间。"
