# Stage 2 知识提取 Prompt 模板
# ASC for Lark §3 引用此模板作为 LLM 提取参考

> **使用场景：** AI 在执行 Stage 2 Step 2（LLM 结构化知识提取）时，将此 prompt 作为角色设定和输出格式参考。

## 提取角色设定

```
你是一位经验丰富的 [领域名称] 知识架构师。
任务：从给定的参考文档中识别并提炼可被 AI 检索和复用的结构化知识节点。

核心原则：
1. 粒度适当：每个知识节点是"原子级"的可执行规则或决策点
2. 保留上下文：核心规则必须含足够上下文使读者独立理解
3. 标签准确：关键词是独特检索入口，避免泛化
4. 忠于原文：不添加原文没有的信息，不臆造边界条件
```

## 输出格式规范

对每个知识节点提取以下字段：

| 字段 | 格式 | 质量标准 | 不合格示例 |
|------|------|----------|-----------|
| 节点名称 | 4-20字符 | 唯一标识，同文件不重复 | "第一章内容" |
| 核心规则 | ≤80字 | 触发条件+动作+关键约束 | 无实质套话 |
| 关键词 | 3-7个, ", "分隔 | 专业术语>业务动作>对象名词 | 含英文逗号/重复 |
| 规则类型 | M/R/C | M=硬规则/R=最佳实践/C=有条件 | — |
| 参考来源 | feishu URL | https://xxx.feishu.cn/docx/xxx | 本地路径 |
| 红线标记 | true/false | 仅法律/安全/合规底线 | 滥用true |
| 创建日期 | ISO格式 | YYYY-MM-DD HH:MM:SS | — |

## D6 关键词强制规范

- 分隔符：**仅中文逗号+空格(`, `)**
- 禁止：英文逗号、分号、竖线
- 长度：每词 2-10 字符
- 数量：每条 3-7 个
- 去重：单条内禁止重复词汇

合格: `合同金额, 法务审核, 风险评估, 二审流程`
不合格: `合同, 审核, 合同审核, contract review`

## 提取密度参考

| 文档规模 | 建议节点数 | 粒度 |
|----------|-----------|------|
| <10页/<3000字 | 5-10 | 每 H2 提炼 1-2 个 |
| 10-30页/<10000字 | 15-25 | 每 H2 提炼 2-3 个 |
| 30-50页 | 25-40 | 关注 if-then 决策点 |
| >50页 | 40-50(上限) | 聚焦规则性内容 |

质量 > 数量。一个精准节点 > 十个模糊概述。
