## Part B：子技能功能

### 测试目标

**验证 ASC 产出的子技能 SKILL.md 是否是一个可独立运行的、自洽的技能文件。**

### T6: 子技能启动序列加载

| 子步骤 | 操作 | 验证标准 |
|--------|------|----------|
| 6.1 | 读取生成的 SKILL.md frontmatter | name/version/description 存在 |
| 6.2 | 解析 LARK_KNOWLEDGE_BASE 块 | 6 个 key 全部有值（非占位符） |
| 6.3 | 解析 DOMAIN_VARIABLES 块 | 至少有 1 个变量定义（快速模式有默认值） |
| 6.4 | 解析 LARK_REQUIRED_SCOPES | 7 个 scope 存在 |
| 6.5 | 模拟 §5.1 授权检查 | tokenStatus = valid → 继续 |
| 6.6 | **关键一致性检查**：LARK_KNOWLEDGE_BASE 中的 table_id 与 Part A 中实际创建的是否一致？ | 一致 ✅ |

### T7: 子技能三级检索模拟

**用真实数据推演三级检索逻辑。**

#### 场景 7A: EL 精确命中

| 项目 | 设置 |
|------|------|
| 用户查询 | "甲方大额合同怎么审核？" |
| 事件 A 提取的变量 | {谈判地位: "甲方", 业务场景: "合同审核"} |
| EL 表实际数据 | 使用 Part A T4 写入的真实记录 |

**预期推演路径：**
```
P1 EL精确匹配:
  → 读取 EL 表 +record-list
  → 解析二维数组
  → 匹配"谈判地位=甲方" → HIGH/MEDIUM?
  → 若有红线=true → 强制纳入
  → 读 link → 获取 KM 详情
  → 组装回复
```

#### 场景 7B: KM n-gram 降级匹配

| 项目 | 设置 |
|------|------|
| 用户查询 | "合同归档有什么规范要求？" |
| EL 表 | 无命中（变量不匹配） |
| KM 表实际数据 | 使用 Part A T3 写入的真实记录 |

**预期推演路径：**
```
P1 → 无 HIGH/MEDIUM → 降级到 P2
P2 KM n-gram:
  → 读取 KM 表 +record-list
  → split("， ") 展开 keywords
  → 计算 score(w, K)
  → score >= 0.5? → 命中 or 未命中
```

#### 场景 7C: 全文降级

| 项目 | 设置 |
|------|------|
| 用户查询 | "公司年会策划流程"（完全无关主题） |
| EL 表 | 无命中 |
| KM 表 | 无命中 |

**预期推演路径：**
```
P1 + P2 均无命中 → P3 全文降级
→ get_node(REF) → docs +fetch
→ 以全文为上下文回答
→ 标注 C11 免责声明
```
